# thought-searcher 확장 명세: 열린 일 큐 + claude.ai 자동 수집

> 본 명세(`SPEC.md`)에 붙는 확장이다. 여기 적지 않은 것은 `SPEC.md`를 따른다.
> 인터뷰: 2026-11-09

## 1. 개요
- 배경: AI 작업이 빨라 여러 일을 동시에 벌이다 보니 무엇을 했고 무엇이 남았는지 기억이 안 남는다. 손으로 관리하는 큐나 할 일 목록은 방치된다.
- 목적: 이미 모으고 있는 기록(Claude Code 대화, Obsidian 업무 일지, 노트, claude.ai 채팅)에서 "열린 일" 목록을 자동으로 만들어 보여 준다. 사용자는 큐를 쓰지 않는다.
- 원칙
  - 일 하나 = 채팅(또는 노트) 하나. 여러 일이 한 채팅에 섞이는 경우는 따로 처리하지 않는다.
  - 최근 14일 안에 흔적이 있으면 열린 일. 흔적이 끊기면 목록에서 숨긴다(삭제 아님, 검색으로는 계속 찾힌다).
  - 직접 닫기는 최소화한다. 일지의 `[x]`가 닫기 신호가 된다.
  - AI는 사용자가 일 하나를 골라 요약 키를 눌렀을 때만 부른다(토큰 절약).

## 2. 범위
### 포함
- **A. 열린 일 큐**: 검색 창의 검색어가 비어 있을 때 보이는 목록
- **B. 업무 일지 읽기**: `YYYY/MM/YYYY-MM-DD.md`의 `## 업무` 구역 항목, 체크 상태, 연결된 세션 ID
- **C. "어디까지 했지?" 요약**: 고른 일 하나를 `claude -p`(Haiku)로 요약, 결과 저장
- **D. claude.ai 자동 수집**: Tampermonkey 사용자 스크립트(저장소에 동봉)가 바뀐 대화만 다운로드 폴더의 수신 폴더에 저장, 앱이 읽어 보관본에 넣음
- **E. 수집 멈춤 알림**: 스크립트 오류는 스크립트가, 스크립트가 조용히 죽은 것은 앱이 알림

### 제외
- 한 채팅 안의 여러 일 분리, 여러 채팅을 하나의 일로 묶기(일지 연결 제외)
- Codex, ChatGPT, 가져온 md(`imported/`), claude.ai 프로젝트 문서와 메모리를 큐에 올리는 것 (검색에는 그대로 나옴)
- 큐 항목 직접 작성, 마감일, 우선순위 지정
- 개인 PC에서의 claude.ai 자동 수집 운영 (스크립트는 어느 PC에서든 동작하게 만들지만 운영 기준은 회사 PC 하나)
- claude.ai에서 지운 대화를 스크립트로 감지하는 것 (공식 zip으로만 missing 처리)
- 일지 파일 쓰기. 앱은 일지를 읽기만 한다(`## 메모 (보고 제외)` 등 다른 구역도 읽지 않음)
- obsidian-log 스킬 수정 자체 (저장소 밖 작업. 이 명세에는 스킬이 남겨야 할 형식만 정한다)

### 본 명세와 달라지는 점
- `SPEC.md` 1번 "AI 토큰을 쓰지 않는다", 2번 제외 "AI 요약"에 예외가 생긴다: C(요약)는 사용자가 키를 누를 때만, 로컬 `claude` CLI를 실행해서 한다. 앱 코드 자체는 여전히 네트워크 모듈을 쓰지 않는다(`test_forbidden_network.py` 유지).
- `SPEC.md` 2번 제외 "claude.ai 자동 내보내기"는 D로 대체된다. 로그인이나 버튼 클릭은 자동화하지 않고, 이미 로그인된 탭에서 사이트 API를 읽는다. 네트워크 접근은 브라우저 안의 스크립트만 한다.

## 3. 기능 요구사항

### A. 열린 일 큐
1. **일의 종류와 id**
   | 일 | id | 출처 |
   |---|---|---|
   | Claude Code 세션 | `claude-code:<세션 id>` (기존 문서 id 그대로) | 기존 수집 |
   | claude.ai 대화 | `claude-ai:<uuid>` (기존 그대로, 프로젝트 문서/메모리 제외) | zip 또는 D |
   | 노트 | `note:<경로>` (기존 그대로) | 노트 폴더. 일지 파일과 `queue_note_exclude` 폴더는 제외 |
   | 연결 안 된 일지 항목 | `journal:<정규화한 항목 제목>` | B. 세션 ID가 없는 항목 |
2. **흔적(trace) 시각**
   - 채팅: 마지막 메시지 시각(문서의 `updated`).
   - 노트: 문서 시각(frontmatter 날짜 > 파일명 날짜 > 수정 시각, 노트 색인과 같은 규칙). 단 큐에는 **파일 수정 시각**을 쓴다(오래된 날짜 노트를 오늘 고쳐도 열린 일로 보이게).
   - 일지 항목: 그 항목이 적힌 일지의 날짜(그날 23:59로 본다. 단 일지 파일을 그 전에 마지막으로 고쳤으면 그 수정 시각. 오늘 일지에 `[x]`를 적은 뒤 같은 날 새 대화를 해도 다시 열리게). 세션 ID로 연결된 채팅이면 그 채팅의 흔적이 하나 더 생기는 것이다.
   - 일의 마지막 흔적 = 위 흔적 중 가장 늦은 것.
3. **열림 판정**: 마지막 흔적이 지금부터 `queue_days`(기본 14)일 안이고, 닫힘 상태가 아니면 열린 일.
4. **닫힘**
   - 일지 신호: 연결된 일지 항목 중 **가장 늦은 날짜의 항목**이 `[x]`면 완료, `[-]`면 버림. 단 그 항목 아래에 `[ ]` 또는 `[/]` 하위 항목(예: `#할일`)이 남아 있으면 열린 채로 둔다.
   - 직접 닫기: 큐에서 완료 또는 버림. `state.json`의 `queue_closed`에 `{id: {"kind": "done"|"drop", "at": 시각}}`로 남긴다.
   - 다시 열림: 닫힌 시각보다 늦은 흔적이 생기면 자동으로 다시 열린다(완료, 버림 모두). 일지 신호로 닫힌 경우도 같다.
   - 되돌리기: 큐 아래 "닫은 일 보기"(최근 `queue_days`일)에서 다시 열 수 있다. `queue_closed`에 `{"kind": "open", "at": 시각}`을 남겨 일지 `[x]`로 닫힌 일도 열리고, 그 뒤 더 늦은 `[x]`가 오면 다시 닫힌다.
5. **표시**
   - 검색 창을 열었을 때 검색어가 비어 있으면 큐를 보여 준다. 글자를 치면 지금의 검색 결과로 바뀌고, 지우면 큐로 돌아온다.
   - 마지막 흔적이 늦은 순서. 위 `queue_focus`(기본 5)개는 크게(제목, 출처 배지, 마지막 흔적 상대 시각, 연결된 일지 항목 한 줄, 저장된 요약 첫 줄), 나머지는 "나머지 N개" 한 줄로 접어 두고 펼칠 수 있다.
   - 열린 일이 없으면 "최근 14일 동안 흔적이 있는 일이 없습니다" 한 줄.
6. **조작** (검색 창과 같은 키는 같은 뜻)
   | 키 | 동작 |
   |---|---|
   | ↑/↓ | 항목 이동 (요약은 저장된 것만 보여 줌, AI 호출 없음) |
   | Enter | 열기: 채팅은 VS Code에서 마지막 메시지 줄, 노트와 일지 항목은 해당 파일 해당 줄 |
   | F2 | 요약 (C) |
   | F4 / Shift+F4 | 완료 / 버림 |
   | 오른쪽 클릭 | 같은 동작 메뉴 |
7. 큐 계산은 UI와 분리한 `app/queue.py`의 순수 함수로 한다(입력: 문서 목록, 일지 항목, 닫힘 기록, 지금 시각 / 출력: 정렬된 일 목록). 창을 열 때마다 계산한다(색인 조회 한 번 + 메모리 계산, 50ms 이하 목표).

### B. 업무 일지 읽기
1. 설정 `journal_dir`(보관함 루트, 기본 빈 값 = 기능 끔). 파일 위치 `YYYY/MM/YYYY-MM-DD.md` 고정. 최근 `queue_days + 1`일치만 읽는다.
2. 읽는 범위는 `## 업무` 제목부터 다음 `## ` 제목 전까지. 다른 구역은 읽지 않는다.
3. **항목** = 들여쓰기 없는 목록 줄 `- [s] 본문`. `s`는 ` `(할 일), `/`(진행), `x`(완료), `-`(버림). 체크 없는 `- 본문`도 항목으로 본다(상태 없음 = 진행으로 취급). 빈 항목(`- `)은 무시.
4. 들여쓴 줄은 그 항목의 하위 내용. 하위의 체크 줄은 "남은 하위 항목" 판정에만 쓴다.
5. **세션 연결**: 항목 줄이나 하위 줄에 인라인 필드 `[session:: <id>]`가 있으면 그 id의 채팅에 연결한다. `<id>`는 Claude Code 세션 id(uuid) 또는 `claude-ai:<uuid>` 같은 문서 id. 여러 개 있으면 모두 연결. 색인에 없는 id면 연결 안 된 항목으로 본다.
6. **정규화한 제목**(연결 안 된 항목의 id): 체크 표시, `#태그`, `[필드:: 값]`, 앞뒤 공백 제거 후 연속 공백 하나로. 같은 제목이 여러 날 일지에 나오면 같은 일이다.
7. 일지 파일은 노트로도 이미 색인된다(검색용). 큐에서는 노트 일로 보지 않는다.
8. obsidian-log 스킬에 요청할 형식(저장소 밖): 업무 항목을 쓸 때 그 일을 한 세션의 id를 `[session:: <id>]`로 항목 하위 첫 줄 끝 또는 항목 줄 끝에 붙인다. Dataview 인라인 필드라 Obsidian 화면에서는 작게 보인다.

### C. "어디까지 했지?" 요약
1. 큐에서 일을 고르고 F2(또는 버튼)를 눌렀을 때만 실행한다. 작업 스레드에서 돌리고, 도는 동안 항목에 "요약 중..." 표시.
2. 재료(입력 상한 `ask_max_chars` 기본 12,000자, 넘으면 오래된 쪽부터 자름)
   - 제목, 출처, 프로젝트
   - 채팅: 보관 md의 마지막 `ask_tail_messages`(기본 20)개 메시지. 노트: 본문 끝부분
   - 연결된 일지 항목(최근 3일치, 하위 내용 포함)
3. 질문: "어디까지 했나 / 남은 일 / 다음 한 걸음" 세 덩어리. 덩어리 머리 한 줄 아래 `1.`부터 번호 붙인 개조식 항목(한 줄 30자 안팎), 항목 수는 3 / 3 / 1개 이하. 원인, 이유, 배경 설명은 쓰지 않는다(물어볼 때만 필요한 내용). 알 수 없는 덩어리는 "1. 기록에 없음".
   - 앱이 답을 다시 정리한다: 머리말과 꾸밈(굵은 글씨, 글머리표)을 지우고, 덩어리마다 번호를 1부터 다시 매기고, 항목 수를 위 상한으로 자르고, 빠진 덩어리는 "기록에 없음"으로 채운다. 형식을 아예 안 지킨 답은 빈 줄만 정리해 12줄까지 둔다.
   - 큐의 큰 줄에는 "다음: (다음 한 걸음)"을 보여 준다. 다음 한 걸음이 없으면 어디까지 했나의 첫 항목.
   - 2026-11-09 실제 일 3개 비교: Haiku 14~23초, Sonnet 16~20초로 둘 다 형식을 지켰고 내용 차이가 작아 기본은 Haiku로 둔다.
4. 실행: `claude -p --model haiku` (모델은 `ask_model` 설정). 재료는 표준 입력으로 넘긴다. 도구를 쓰지 않게 하고, 이 호출이 Claude Code 세션 기록으로 남지 않게 한다(남는다면 전용 작업 폴더 `%LOCALAPPDATA%\thought-searcher\ask\`에서 실행하고 그 프로젝트를 수집에서 뺀다). 제한 시간 `ask_timeout_seconds` 기본 120초.
5. 결과는 `%LOCALAPPDATA%\thought-searcher\summaries.json`에 `{id: {"trace_at", "text", "model", "at"}}`로 저장한다. 다음에 고르면 저장본을 바로 보여 주고, 저장 뒤 새 흔적이 생겼으면 "요약 이후 새 흔적 있음 (F2로 새로)"를 붙인다. 자동으로 다시 부르지 않는다.
6. 실패(`claude` 없음, 로그인 안 됨, 시간 초과, 오류 종료): 항목 아래에 사유 한 줄 + 트레이 알림. 재료는 그대로 버린다.

### D. claude.ai 자동 수집
1. **스크립트**: `thought-searcher/userscript/claude-sync.user.js`. 사용자가 Tampermonkey에 붙여 넣어 설치한다. `@match https://claude.ai/*`, `@grant GM_download GM_getValue GM_setValue GM_notification`.
2. **주기**: 페이지가 열려 있는 동안 `sync_minutes`(기본 30)분마다, 그리고 페이지를 연 직후 한 번. 여러 탭이 열려 있으면 하나만 돈다(`GM_setValue`의 잠금 + 시각).
3. **바뀐 대화 찾기**: 조직 id를 얻고, 대화 목록 API를 최근 수정 순으로 훑으며 `updated_at`을 `GM_getValue("seen")`의 `{uuid: updated_at}`과 비교한다. 이미 본 값보다 오래된 대화가 연속으로 나오면 훑기를 멈춘다.
4. **받기**: 바뀐 대화마다 대화 본문 API(가지 정보 포함)를 받는다. 한 번 돌 때 최대 `max_per_run`(기본 50)개, 요청 사이 1초 이상. 첫 실행에서는 전체 대화를 여러 번에 나눠 받는다.
5. **저장 형식** (대화 하나 = 파일 하나, 같은 대화는 같은 파일을 덮어씀)
   - 경로: 다운로드 폴더의 `claude-sync/claude-ai_<uuid>.json`
   - 내용:
     ```json
     {"format": "thought-searcher.capture/1", "site": "claude-ai",
      "captured_at": "ISO 시각", "project": "프로젝트 이름 또는 null",
      "data": { "...대화 본문 API 응답 그대로..." }}
     ```
   - `data`는 고치지 않는다. 해석은 앱이 한다(사이트 형식이 바뀌면 Python만 고치면 되고, 저장된 원본으로 다시 변환할 수 있음).
   - `project`는 프로젝트 목록 API로 얻은 이름(대화에는 프로젝트 uuid만 있음).
6. **상태 파일**: 매번 돌고 나서 `claude-sync/_status.json`을 덮어쓴다: `{"format": "thought-searcher.capture-status/1", "last_run", "last_ok", "saved", "error"}`.
7. **오류 처리**: 401/403(로그아웃), 429(요청 과다), 형식 오류, 다운로드 실패는 `GM_notification`(크롬이 Windows 알림으로 띄움)으로 알리고 `_status.json`에 `error`를 남긴다. 같은 오류 알림은 6시간에 한 번. 429는 다음 주기까지 쉰다.
8. **앱 쪽 수신**
   - 설정 `capture_dir`(기본 `<watch_dir>\claude-sync`). zip 감시와 같은 방식(폴더 변경 알림 + 주기 확인)으로 `claude-ai_*.json`만 읽는다. `.crdownload`, `.tmp`, 읽다가 JSON이 깨진 파일은 건너뛰고 다음 확인 때 다시 본다.
   - 새 가져오기 모듈 `app/importers/claude_capture.py`: `format`을 보고 판별, `data`를 기존 `claude_export.convert_conversation`으로 변환(API 응답이 내보내기 형식과 다른 부분만 이 모듈에서 맞춘다). `project`가 있으면 프로젝트 이름으로 쓴다.
   - id는 `claude-ai:<uuid>`로 zip과 같다. 같은 대화가 zip과 수집 파일 양쪽에서 오면 `updated`가 늦은 쪽이 남는다. 수집 파일은 missing 처리를 하지 않는다.
   - 처리 이력은 `state.json`의 `capture_files: {파일명: {"mtime", "size", "updated"}}`. 바뀐 파일만 다시 읽는다. 파일은 지우지 않는다. 받은 원본은 `raw/claude-ai-capture/`에도 복사한다(다운로드 폴더 정리 대비).
   - 수집으로 가져온 것은 주간 내보내기 알림 기준(`last_zip_import`)을 바꾸지 않는다(프로젝트 문서, 메모리는 여전히 zip으로만 들어옴).

### E. 수집 멈춤 알림 (앱)
- `capture_dir/_status.json`이 있는데 `last_ok`가 `capture_stale_hours`(기본 3)시간보다 오래됐으면 트레이 알림 "claude.ai 자동 수집이 N시간째 멈춰 있습니다". 하루 한 번까지. `_status.json`이 한 번도 없었던 PC(개인 PC)에서는 알리지 않는다.
- 상태 창(`status_text`)에 "claude.ai 자동 수집: 마지막 성공 HH:MM, 대화 N개" 줄 추가.

## 5. 엣지 케이스
- 같은 세션 id가 여러 날 일지에 나옴: 날짜마다 흔적. 닫힘 판정은 가장 늦은 날의 항목 상태.
- 한 항목에 세션 id가 두 개: 두 채팅 모두에 같은 흔적과 상태가 붙는다.
- 일지에 적힌 세션 id가 아직 수집 전(30분 주기): 연결 안 된 항목으로 보였다가, 수집 뒤 채팅에 붙는다(id만 바뀌므로 직접 닫기 기록은 `journal:` id에 남아도 무시됨).
- 연결 안 된 항목 제목을 다음 날 조금 고쳐 씀: 다른 일로 보인다(받아들임. 세션 id를 남기는 것이 해법).
- 요약용 `claude -p` 실행이 세션 기록을 남김: 3-C-4대로 수집에서 뺀다. 안 빼면 요약 호출마다 새 일이 생긴다.
- 노트를 Obsidian이 열기만 해도 수정 시각이 바뀌는 경우: 큐에 잠깐 올라올 수 있다(받아들임).
- 크롬이 탭을 메모리 절약으로 잠재움: 스크립트가 멈춘다. README에 claude.ai를 "항상 활성 상태로 유지할 사이트"에 넣으라고 적고, E가 잡는다.
- Tampermonkey 다운로드 모드가 기본값: 하위 폴더 대신 다운로드 폴더 바로 아래 `파일 (1).json`이 쌓인다. 스크립트가 첫 저장 뒤 확인할 방법이 없으므로, README에 설정(Browser API 모드, `.json` 허용)을 적고 앱이 다운로드 폴더 바로 아래 `claude-ai_*.json`을 발견하면 "Tampermonkey 다운로드 설정 확인" 트레이 알림을 한 번 띄운다.
- 수집 파일이 반쯤 써진 상태: JSON이 깨지면 다음 확인 때 다시 읽는다.
- 회사 PC 크롬에 개인 대화도 저장됨: 사용자 확인 사항(괜찮음).

## 6. 제약
- 앱의 큐 화면은 창을 열 때 100ms 안에 보여야 한다(대화 2천 개 기준).
- 앱은 네트워크 모듈을 쓰지 않는다. `claude` CLI 실행은 F2를 눌렀을 때만.
- 스크립트는 claude.ai 비공식 API에 기대므로 사이트가 바뀌면 멈출 수 있다. 요청은 바뀐 대화만, 주기당 상한을 둔다.
- 저장소에는 개인 경로(보관함 위치, 폴더 이름)를 기본값으로 넣지 않는다.

## 9. 가정 (구현 중 바꿀 수 있음)
- 요약, 닫기 키는 F2, F4, Shift+F4. 검색 창 입력란에 초점이 있어도 동작한다.
- 연결된 일지 항목이 있는 채팅은 큐에서 일지 항목 본문을 부제목으로 보여 준다.
- 큐의 노트 흔적은 파일 수정 시각을 쓴다.
- 일지 날짜의 흔적 시각은 그날 23:59(로컬). 단 파일 수정 시각이 그보다 이르면 수정 시각(2단계 구현 때 바꿈).
- 일지 항목이 가리키는 세션이 Claude Code, claude.ai 대화가 아니면(Codex 등) 연결 안 된 항목으로 본다.
- 체크 없는 일지 항목은 진행 상태로 본다.
- 첫 수집은 전체 대화를 주기당 50개씩 나눠 받는다.
- 요약 결과는 PC 밖으로 나가면 안 되는 기록으로 보고 `%LOCALAPPDATA%`에 둔다.

## 10. 미결 사항 (구현 전 확인)
- ~~세션 id를 일지 스킬이 얻는 방법~~ (2026-11-09 확정, Claude Code 2.1.317): Bash 도구 환경 변수 `CLAUDE_CODE_SESSION_ID`가 현재 세션 id(원본 jsonl 파일 이름)와 같고, 서브에이전트의 Bash에서도 메인 세션 id가 나온다. 스킬 본문 치환 `${CLAUDE_SESSION_ID}`도 있다. 스킬이 이 값으로 `[session:: <id>]`를 남기는 방식으로 확정. jsonl에서 일지 Edit/Write를 찾는 대안은 버림(obsidian-log 서브에이전트가 Bash로만 쓰는 경우가 많아 놓침).
- ~~`claude -p` 옵션~~ (2026-11-09 확정): `claude -p --model haiku --no-session-persistence --tools "" --disable-slash-commands --strict-mcp-config`. `--no-session-persistence`는 세션을 디스크에 저장하지 않고, `--tools ""`는 내장 도구를 모두 끈다. 그래도 전용 작업 폴더 실행과 수집 제외(3-C-4)는 보험으로 둔다. (3단계 구현 때 실제 실행으로 확인: Haiku 응답 약 27초, 세션 jsonl은 남지 않고 작업 폴더 이름의 빈 `memory/` 폴더만 생김) 개인 PC에는 PATH에 `claude`가 없어(npm 전역 설치는 네이티브 바이너리 누락, 데스크톱 번들은 앱 밖에서 로그인 안 됨) 3단계 전에 CLI 설치와 로그인이 필요하다.
- ~~claude.ai API 응답 구조~~ (2026-11-10 확인, 실제 수집 파일 87개): 대화 본문 API(`tree=True&rendering_mode=messages`)는 내보내기와 필드가 거의 같아 `convert_conversation`을 그대로 쓴다. 다른 점과 맞춤:
  - `current_leaf_message_uuid`가 있어 지금 보는 가지를 본선으로 삼는다(내보내기 변환도 있으면 쓰게 바꿈).
  - AI가 만들어 건넨 파일이 메시지 `files`가 아니라 도구 블록 안에만 있다(`present_files` 입력의 `filepaths`, 도구 결과의 `file_deliveries`). 이름을 모아 첨부 줄로 넣는다.
  - 본문에 내보내기의 `<cite index=...>` 꼬리표가 없다(인용은 `citations`에 따로). 그대로 둔다.
  - 내보내기가 붙이는 `image-0-0.jpg` 같은 생성 이미지 이름은 API에 없다. 버린다.
  - 같은 대화 83개 중 65개 본문이 zip 변환과 같았고, 나머지는 위 차이와 zip 이후 이어진 대화였다.
- 회사 PC에서 Tampermonkey 설치와 `GM_download` 하위 폴더 저장이 허용되는지(사내 보안 프로그램, 크롬 정책). 개인 PC에서는 2026-11-10 Browser API 모드로 `claude-sync/` 하위 폴더 저장 확인.
- 회사 PC에서 `claude` CLI가 PATH에 있는지.

  4. 오늘 일지에 `[session:: <오늘 세션 id>]` 항목을 넣음 → 그 세션에 부제목이 붙음 → `[x]`로 바꿈 → 큐에서 빠짐 → 그 세션에서 새 대화 → 다시 나타남
  5. F2 → 10~30초 안에 요약 표시 → 창을 닫았다 열면 저장본이 바로 보임 → 큐에 요약 호출로 생긴 새 세션이 없음
  6. F4 → 빠짐, "닫은 일 보기"에서 다시 열기
  7. 회사 PC: 스크립트 설치 → 첫 실행 → `다운로드\claude-sync\`에 파일 생성 → 앱이 가져와 `src:ai` 검색에 나옴 → claude.ai에서 대화 하나 이어 씀 → 30분 안에 그 파일만 바뀌고 큐 맨 위로
  8. 크롬에서 claude.ai 로그아웃 → Windows 알림. 탭을 닫고 3시간 뒤 → 앱 트레이 알림

## 13. 사람 검토 체크포인트
1. **구현 시작 전**: 10번 미결 중 세션 id 얻는 방법과 `claude -p` 옵션을 구현 세션이 조사해 보고 → 사용자가 연결 방식 확정
2. **1단계 후**: 큐 첫 화면(크기, 정보량, 접기) 확인
3. **3단계 후**: 실제 일 3개의 요약을 보고 질문 문구와 재료 양 조정
4. **4단계 시작 전**: 사용자가 회사 PC에서 시험 스크립트로 받은 실제 수집 파일 1~2개를 `tests/local/`에 넣음 → 구조 확인 후 변환 맞춤 범위 승인
5. **일주일 사용 후**: `queue_focus` 개수, 14일 기간, 큐에 잡음처럼 올라오는 일(짧은 질문 세션 등) 정리 방법 결정
