# 검색창, 설정창 새 디자인 구현 계획

2026-11-12 opus 채팅에서 시안을 보고 정한 내용. 구현은 이 문서를 기준으로 한다.
시안은 Kiro Crew 대시보드 아티팩트 "검색창 시안 D: B+C 섞음", "설정창 시안 B+C"에 있다.
색 값은 모두 `app/theme.py`의 기존 값을 쓴다. 새 색 값을 만들지 않는다.

## 정한 것

### 검색창 (시안 D)
- 창 머리: 큰 검색칸(20px 안팎 글자, 돋보기 아이콘, 오른쪽에 결과 수). 그 아래 얇은 선.
- 결과 줄: 한 줄(배지, 제목, 프로젝트, 날짜 MM-DD). 고른 줄은 바탕색 + 왼쪽 강조색 막대 3px.
- 창 폭에 따라 바뀜 (기준 760px, 상수로 둔다):
  - 좁음: 목록만. 고른 줄만 두 번째 줄에 맞은 메시지 미리보기와 `← i/n →`.
  - 넓음: 왼쪽 목록(기본 40%) | 나누기 막대 | 오른쪽 미리보기 칸. 목록 줄은 모두 한 줄.
- 미리보기 칸: 배지+제목, 출처·프로젝트·날짜 시각, "맞은 메시지 i / n", 맞은 메시지와 그 앞뒤 메시지 1개씩.
  맞은 메시지는 왼쪽 강조색 선 + 옅은 바탕(sidebar), 앞뒤는 sub 색. 맞은 낱말은 mark_bg.
- 아래 막대(sidebar 바탕, 위 얇은 선): 설정 아이콘, "생각 검색기", 오른쪽에 `열기 Enter`(굵게), `메시지 복사 Ctrl Enter`, `대화 복사 Shift Enter`(좁으면 숨김). 키는 키캡 모양.
- 창 모서리 둥글게: Windows 11은 DWM `DWMWA_WINDOW_CORNER_PREFERENCE`(33)로. 안 되는 환경은 사각형 그대로 둔다. 반투명 창 + 그림자 흉내는 하지 않는다.
- 날짜 묶음 줄("최근 3개월/그 이전")은 넣지 않는다. 검색 결과는 관련도 순이라 날짜로 묶으면 순서가 깨진다.
- 큐(빈 검색어) 화면: 같은 줄 모양을 쓴다. 넓을 때 오른쪽 칸에는 지금 `detail` 라벨이 보여 주던 저장된 요약을 보여 준다(AI 호출 없음). 좁을 때는 지금처럼 목록 아래.

### 창 크기 저장
- 테두리 6px와 오른쪽 아래 모서리 표시를 끌면 크기가 바뀐다. `QWindow.startSystemResize(edges)` 사용.
- 목록/미리보기 나누기는 `QSplitter`. 위치도 저장.
- 저장 위치: `store.local`(LOCALAPPDATA) 아래 `ui_state.json`. 모니터가 PC마다 달라서 config.json(APPDATA)에 넣지 않는다. 설정창에는 항목을 만들지 않는다.
- 저장 시점: 크기 조절, 나누기 끌기가 끝났을 때(디바운스) 또는 창 숨길 때.
- 열 때 저장된 크기가 그 모니터 사용 가능 영역보다 크면 줄인다. 최소 크기 560x360.

### 설정창 (시안 B+C)
- 창 머리: 설정 찾기 칸. 강조색 테두리 1.5px, 강조색을 옅게 깐 바탕(라이트 약 7%, 다크 약 11%), 강조색 돋보기. 비었을 때 오른쪽에 `Ctrl F`, 입력 중에는 맞은 수(강조색 굵게).
- 찾기: 모든 탭의 줄(이름 + 설명 + 툴팁 글)에서 찾는다. 맞는 줄만 남기고, 줄이 없는 섹션은 숨긴다. 사이드바 탭 이름 옆에 맞은 수 배지(옅은 강조색 바탕, 강조색 글자). 맞은 게 없는 탭은 흐리게. 지금 탭에 맞은 게 없으면 맞은 게 있는 첫 탭으로 옮긴다. 맞은 글자는 mark_bg.
- 사이드바: 지금 모양 유지 + 고른 탭에 왼쪽 강조색 막대 3px.
- 섹션: 제목(+옆 설명) 아래 카드 하나. 카드 바탕 sidebar, 테두리 line, 모서리 9px. 줄 사이는 line 색 얇은 선.
- 줄은 두 줄까지:
  - 보통 줄: 왼쪽 `이름(굵게) + ⓘ` / `설명 한 줄`, 오른쪽 입력칸.
  - 넓은 입력(강조색, 목록, 여러 줄 정규식 등): `이름 + 설명`이 한 줄, 그 아래 입력칸.
- 설명이 길면 한 줄에 필요한 말만 남기고 나머지는 이름 옆 ⓘ 툴팁으로 옮긴다. 형식을 꼭 알아야 하는 항목(업무 일지 폴더 형식 등)은 칸이 비어 있을 때만 설명 줄에 그 형식을 보인다.
- 모드 선택은 붙은 버튼(세그먼트) 모양. 단축키 칸은 키캡 모양.
- 아래 막대: 바뀐 설정이 있으면 강조색 점 + "바뀐 설정 N개", 오른쪽 `취소 Esc`, `저장 Ctrl S` 안내와 버튼. Ctrl+S, Ctrl+F 단축키 추가. Esc는 지금 동작(변경 있으면 확인) 유지.
- 시작 안내(setup_mode)도 같은 카드, 아래 막대 모양을 쓴다. 찾기 칸은 시작 안내에는 넣지 않는다.

## 순서

1. `theme.py`: 키캡, 찾기 칸, 카드, 강조색 막대, 결과 막대 스타일과 옅은 강조색 계산 함수(`_blend` 재사용). 색 값은 추가하지 않는다.
2. 검색창 크기 조절 + `ui_state.json` 저장/복원 + 화면 맞춤. (기능만, 모양 변경 전)
3. 검색창 모양: 머리, 한 줄 결과 delegate, 좁음/넓음 전환, `QSplitter`, 미리보기 칸, 아래 막대, 둥근 모서리.
   - 미리보기 내용은 hit의 md를 `mdparse`로 읽어 `MatchedMessage.ordinal` 앞뒤를 고른다. 고른 줄이 바뀔 때 디바운스, md 경로+수정시각으로 캐시. 원본 없음(missing)이면 "원본 없음" 한 줄.
   - ←/→는 지금처럼 맞은 메시지를 바꾸고, 넓을 때 미리보기도 따라간다.
4. 설정창: 카드 섹션, 두 줄 줄 구조, ⓘ 툴팁, 찾기 칸과 필터, 사이드바 배지, 아래 막대, 단축키.
5. 문구: impeccable `clarify`로 설정창 모든 탭(일반, 수집, 요약 AI, 고급)의 설명을 "줄인 설명 / 툴팁" 표로 만든다. CG 확인을 받은 뒤 반영한다(사실을 담은 문구라 확인 없이 바꾸지 않는다).
6. 확인: `pytest` 전체 통과. 문구를 바꿔 깨지는 테스트는 기대값을 새 문구로 고친다. `QWidget.grab()`으로 검색창(좁음/넓음, 검색/큐) x 라이트/다크, 설정창(일반, 찾기 중) x 라이트/다크를 한 번에 찍어 확인.
7. 기록: `docs/handoff.md` 맨 위 새 절, README 화면 설명 갱신, 이 문서는 남겨 둔다.

각 단계 끝에 테스트를 돌리고 커밋한다. push는 CG가 직접 한다.

## 건드리지 않는 것
- 키 조작, 검색 문법, 검색 순위, 큐 규칙, 설정 항목과 저장 형식(config.json).
- 확인 창(`ask`/`tell`) 동작. 모양만 새 스타일을 따른다.
