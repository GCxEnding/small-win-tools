# 검색 개선 계획: 메시지 시각, 정렬, 내 질문만, 한영 자동 보정

2026-11-12 opus 채팅에서 CG와 정한 내용. 구현은 이 문서를 기준으로 하고 단계마다 따로 커밋한다.

## 알아낸 것
- 메시지마다 시각은 이미 보관 md에 있다. 표시 줄 `<!-- bs:msg N role CREATED -->`와 제목 `## 🧑 사용자 (2026-10-01 10:00)`. `mdparse.ParsedMessage.created`도 이미 읽는다. claude.ai, Claude Code, ChatGPT, Codex 모두 메시지 시각을 넣는다.
- 빠진 곳은 검색 색인뿐이다. `index.py`의 `messages` 표에 `created`가 없다.
- `index.SCHEMA_VERSION`을 올리면 다음 실행 때 md에서 색인을 다시 만든다(zip, 원본은 다시 읽지 않음).
- 지금 검색은 맞는 대화를 모두 가져와 점수를 매긴 뒤 자른다(`Searcher._rank`). 정렬 방식을 바꿔도 후보는 같다.
- 노트는 메시지 단위 시각이 없다(구역만 있음). 노트와 일지는 지금처럼 문서 시각을 쓴다.

## 정한 것

### 1. 메시지 시각 색인 (CG: 개선)
- `messages`에 `created_ts REAL`(UTC 초) 추가, `SCHEMA_VERSION` 2. 시각이 없는 메시지(노트 구역 등)는 문서 `updated_ts`.
- 대화마다 **채팅 시각** = 맞은 메시지 중 가장 늦은 메시지의 시각. 기간 조건이 있으면 그 안에서 고른다.

### 2. 기간 필터를 메시지 기준으로 (CG: 개선)
- 검색어가 있을 때 `after:`, `before:`, 기간 칩은 **맞은 메시지 중 하나 이상이 기간 안**이면 남긴다. 지금은 대화 마지막 시각(`updated_ts`) 기준이라, 1년 전 대화에 어제 한 줄을 이으면 1주 칩에 걸린다.
- 단어 없이 칩만 켠 경우(큐 거르기)와 빈 검색어 큐는 지금 그대로.
- 미리보기와 `←/→`는 기간 안의 맞은 메시지만 돈다.

### 3. 정렬
- `정확도`(지금 순위) / `최신`(채팅 시각 순). 기본값 `최신`.
- 칩 둘째 줄 오른쪽 끝에 붙은 버튼 `정확도 | 최신`. 단축키 `Ctrl+R`로 바꿈.
- 설정 `search_sort`("recent" | "relevance", 기본 "recent"), `설정 > 일반 > 검색 창 > 기본 정렬`. 창에서 바꾼 것은 그 검색에만, 창을 열 때(`popup()`) 기본값으로 돌아간다(칩과 같은 규칙).
- 최신순일 때 대화 안 맞은 메시지도 늦은 것부터 보여 준다(미리보기 첫 메시지, `←/→` 순서). 정확도순은 지금 순서.
- 영어 앞부분 일치(`log`→`logpick`) 때문에 최신순에서 약하게 맞은 대화가 위로 올 수 있다. 일단 그대로 두고 써 보고 정한다.

### 4. 화면에 채팅 시각 표시 (CG: 마지막 채팅 시각은 유지)
- 결과 줄 오른쪽: 채팅 시각 `MM-DD`. 마지막 채팅 시각과 날짜가 다르면 그 뒤에 흐리게 `· 마지막 MM-DD`. 같으면 하나만.
- 미리보기 머리: 지금 줄(출처, 프로젝트, 날짜 시각)은 `마지막 YYYY-MM-DD HH:MM`으로 이름을 붙여 유지하고, `맞은 메시지 i / n` 옆에 그 메시지의 시각.
- 미리보기 메시지마다 `나 · MM-DD HH:MM` / `AI · MM-DD HH:MM`.
- 최신순, 정확도순 모두 같은 표시.

### 5. 내 질문만 (`by:me`)
- 새 문법 `by:me`(별칭 `by:나`). 모든 검색 단어가 그 대화의 **사용자 메시지**에 있어야 한다(같은 메시지일 필요 없음). 미리보기, `←/→`, 채팅 시각도 사용자 메시지만.
- 칩 둘째 줄에 `내 질문` 칩(정렬 버튼 앞). 창을 열 때 꺼짐.
- AI 답만 찾는 기능은 만들지 않는다(CG: 답이 너무 많아 쓸모가 적음).
- 노트, 일지, 프로젝트 문서, 메모리는 사용자 메시지가 없으므로 `by:me`에서 빠진다.

### 6. 한영 자동 보정
- 결과가 0건일 때만 한다. 검색 단어(문법 토큰 `src:` 등과 따옴표 구문 밖의 낱말) 하나씩:
  - 한글 자모가 영문 자판으로 친 것처럼 보이면(`ㅜㅎㅑㅜㅌ`) 영문으로(`nginx`)
  - 영문 소문자가 한글 자판 오타처럼 보이면(`qovh`) 한글로(`배포`). `emoji-searcher/app/hangul.py`의 `latin_to_hangul`, `is_keyboard_latin`을 이 앱으로 복사해 쓴다(도구끼리 import하지 않음, 저장소 폴더 규칙).
- 바꾼 검색어로 다시 찾아 결과가 있으면 그 결과를 보이고, 상태 자리에 `nginx로 찾았습니다`. 검색칸 글자는 바꾸지 않는다.
- 바꿔도 0건이면 원래대로 0건.

### 7. 0건 안내 (CG: 넣음)
- 한영 보정(6번)까지 해도 0건이고 조건(출처 칩, 기간 칩, 프로젝트 칩, `내 질문`, 손으로 친 `src:` `after:` `before:` `proj:` `by:` `-제외어`)이 하나 이상 있을 때만.
- 조건을 하나씩 빼고 결과 수를 센다(검색은 수만 세고 결과는 만들지 않음). 가장 많이 나오는 조건 하나를 안내한다. 하나만 빼서는 0건이면 조건을 모두 뺀 수를 센다.
- 문구(CG 지정): `출처를 제외하면 12건입니다`. 조건 이름은 출처 / 기간 / 프로젝트 / 내 질문 / 제외어 / 모든 조건. 목록 자리 빈 줄 대신 이 한 줄을 보인다.
- 누르거나 `Enter`를 치면 그 조건을 끄고 다시 찾는다. 칩이면 칩을 끄고, 손으로 친 토큰이면 검색칸에서 그 토큰을 지운다.
- 조건이 없거나 모두 빼도 0건이면 지금처럼 결과 없음.

### 8. 날짜 묶음 줄 (CG: 넣음)
- 최신순 검색 결과에만. 채팅 시각 기준으로 `오늘` / `이번 주`(월요일 시작, 오늘 제외) / `이번 달`(앞 둘 제외) / `그 전`. 해당 결과가 없는 묶음은 줄을 만들지 않는다.
- 묶음 줄 모양: 작은 sub 색 글자 + 오른쪽으로 이어지는 line 색 가는 선. 고를 수 없는 줄이라 `↑/↓`가 건너뛴다(큐의 접기 줄과 달리 동작 없음).
- 정확도순, 큐, 칩만 켠 목록에는 넣지 않는다.

## 순서
1. 메시지 시각 색인 + 기간 필터 메시지 기준 + 채팅 시각 계산(검색 엔진만, 화면 변경 없음). 테스트: 1년 전 메시지만 맞고 어제 다른 메시지가 있는 대화가 1주 칩에 안 걸림, 채팅 시각이 맞은 메시지 시각, 스키마 2로 올라갈 때 자동 재색인.
2. 정렬(엔진 + 칩 줄 버튼 + `Ctrl+R` + 설정 `search_sort`) + 화면의 채팅 시각 표시 + 날짜 묶음 줄.
3. `by:me` 문법과 `내 질문` 칩 + 한영 자동 보정 + 0건 안내 (CG: 한 단계로 묶음).
각 단계: `python -m pytest -q --deselect tests/test_perf.py` 통과(속도 테스트는 단계마다 돌리지 않음, CG 지시), 커밋 `thought-searcher: `, push 안 함. `docs/handoff.md` 맨 위 절과 README(검색 문법 표, 검색 창 화면, 설정 창 표) 갱신.

4. 마무리 확인: 모든 단계가 끝난 뒤 `python -m pytest -q tests/test_perf.py`를 한 번 돌려 작업 전 커밋(`89a7794`)과 시간을 비교한다. 느려졌으면 그때 고친다.

## 건드리지 않는 것
- 정확도순 점수 계산(`_rank`), 큐 규칙, 기존 검색 문법의 뜻(기간만 메시지 기준으로 바뀜), config.json 기존 키.

## 1단계 보충 (구현하며 정한 것)
- **맞은 메시지**는 검색어 중 하나라도 들어 있는 메시지다. 미리보기가 맞은 메시지를 고르는 방식과 같다. 대화 후보는 지금처럼 모든 단어가 대화 안에 AND로 있어야 한다.
- 단어가 제목에만 맞아 맞은 메시지가 없는 대화는 예전 대화 단위 기간 조건(`updated_ts`, `created`)으로 판단하고, 채팅 시각은 `updated_ts`로 한다. 본문에 맞은 메시지가 있는데 모두 기간 밖이면 살리지 않는다.
- 한 글자 검색어만 있는 질의(제목 부분 일치)와 단어 없는 질의는 예전 그대로이고, `chat_time`은 `updated_ts`다.
- `chat_time`은 `Hit.chat_time`(로컬 시간대 `datetime`)으로 내보낸다. 기간 안의 `matches`와 `match_total`만 센다.
- 속도 테스트(`tests/test_perf.py`)는 CG 지시로 모든 단계가 끝난 뒤에 따로 확인한다.
