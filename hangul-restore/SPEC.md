# hangul-restore 명세

> 저장소: `GCxEnding/small-win-tools` (공개)
> 위치: `small-win-tools/hangul-restore/`

## 1. 개요
- 목적: 레거시 Java/Tomcat/Oracle 환경에서 자주 보는 깨진 한글(인코딩 오독, URL 인코딩, 유니코드 이스케이프, HTML 엔티티, Base64)을 클립보드에 복사하고 단축키 한 번으로 복원한다. 복원 결과와 함께 **어디서 어떻게 깨졌는지**(복원 경로와 의심 지점)를 보여 준다.
- 사용자: CG 본인 (회사 PC, 집 PC). 공개 레포이므로 같은 문제를 겪는 다른 개발자도 쓸 수 있게 한다.

## 2. 범위
### 포함
- 트레이 상주, 전역 단축키(Win+Shift+K)로 클립보드 내용 해독 팝업
- 여러 줄 문자열, 정상 텍스트와 깨진 구간이 섞인 입력의 부분 복원
- 복원 연산 최대 3단계 조합 탐색
- 후보 점수화("한글다움"), 상위 후보 목록, Enter로 복사
- 복원 경로 표시와 원인 힌트 (규칙 파일)
- 손실된 글자 □ 표시와 "일부 손실" 판정
- 명령줄 없이 테스트 가능한 순수 함수 코어

### 제외 (Out of scope)
- 파일 입력, 파일 인코딩 판별
- 선택 영역 자동 복사 (터미널에서 Ctrl+C 전송 위험)
- 한국어 외 언어(일본어, 중국어) 복원 판정. 결과에 한자/가나가 나와도 정답으로 취급하지 않음
- epoch, cron, JWT 등 일반 텍스트 해석 ("선택 텍스트 X-ray"는 후속 과제)
- 네트워크 사용

## 3. 기능 요구사항
1. **호출**
   - `hangul_restore.pyw` 실행 시 트레이 상주. Win+Shift+K 누르면 클립보드 텍스트로 팝업을 띄운다.
   - 단축키 등록 실패 시 `fallback_hotkey`(기본 Ctrl+Alt+K)로 등록하고 트레이 알림. 둘 다 실패하면 트레이 메뉴 `열기`로만 사용.
   - 팝업 입력란에 클립보드 내용이 채워져 있고, 사용자가 직접 수정하거나 붙여 넣어 다시 해독할 수 있다(입력 변경 시 즉시 재계산).
   - 클립보드에 텍스트가 없으면 빈 입력란 + 안내 문구.
2. **복원 연산 (decoders)**
   각 연산은 `str -> str | None` (적용 불가면 None).
   - 인코딩 오독 되돌리기: "텍스트를 A로 인코딩한 바이트를 B로 디코딩" 조합.
     - A(잘못 읽은 쪽): cp949, euc-kr, latin-1, cp1252
     - B(원래 인코딩): utf-8, cp949
     - 대표 경로: `UTF-8 바이트를 CP949로 읽음` (`寃곗옱` → `결재`), `CP949 바이트를 Latin-1로 읽음` (`°áÀç` → `결재`)
   - URL 디코딩: `%EA%B2%B0%EC%9E%AC` → `결재` (UTF-8, CP949 각각 시도, `+`는 공백)
   - 유니코드 이스케이프: `결재` → `결재` (대소문자, `\U0000XXXX`, 서로게이트 쌍 포함)
   - HTML 엔티티: `&#44208;&#51116;`, `&#xACB0;`, `&amp;` 등
   - Base64: 표준/URL-safe, 패딩 누락 허용. 디코딩한 바이트를 UTF-8, CP949로 읽어 **결과가 유효한 한글일 때만** 후보로 인정
3. **탐색**
   - 입력에서 시작해 연산을 최대 3단계까지 조합한다(BFS). 예: `%E5%AF%83%EA%B3%97%EC%98%B1` → URL 디코딩 → `寃곗옱` → UTF-8을 CP949로 읽음 되돌리기 → `결재`.
   - 같은 결과 문자열은 가장 짧은 경로 하나만 남긴다.
   - 결과가 입력과 같거나 점수가 개선되지 않는 단계는 가지치기한다.
   - 전체 탐색은 일반 입력(수 KB)에서 체감 지연 없이 끝나야 한다(목표 200ms). 입력이 `max_input_chars`(기본 20,000자)를 넘으면 앞부분만 처리하고 안내.
4. **부분 복원 (섞인 입력)**
   - 입력을 "정상 구간"(ASCII 영숫자, 공백, 일반 기호, 정상 한글 음절)과 "의심 구간"(깨짐 문자, `%XX` 연속, `\uXXXX` 연속, `&#...;` 연속, Base64 형태 토큰, Latin-1 확장 문자, 의심 한자/희귀 한글 음절 연속)으로 나눈다.
   - 의심 구간마다 독립적으로 탐색하고, 전체 문장에 대해 각 구간의 최선 결과를 조합한 후보를 만든다.
   - 예: `ERROR userNm=�솉湲몃룞 id=1004` → `ERROR userNm=` 와 ` id=1004`는 유지, 가운데만 복원.
   - 전체를 한 덩어리로 본 결과도 후보로 함께 경쟁시킨다(구간 나누기가 틀릴 수 있으므로).
5. **점수 ("한글다움")**
   - 가산: 자주 쓰는 한글 음절 비율 (동봉 빈도표 기준 상위 2,350자 KS X 1001 완성형 우선), 정상 ASCII 유지
   - 감산: `�`(U+FFFD), 제어 문자, 사용 빈도가 매우 낮은 한글 음절, 한자/가나(원래 입력에 없던 경우), Latin-1 확장 문자, 사설 영역 문자
   - 경로가 길수록 약간 감산 (같은 점수면 짧은 경로 우선)
   - 입력 자체가 이미 정상이면 "깨진 부분을 찾지 못했습니다"를 표시하고 원문을 1위로 둔다.
6. **손실 처리**
   - 복원 결과에 `�`가 남거나, 원본에 `?`/`�`로 이미 대체된 바이트 때문에 한 글자를 완성하지 못하면 그 자리를 `□`로 표시하고 후보에 "일부 손실" 라벨을 붙인다.
   - 손실 글자 수를 함께 표시한다(예: "2글자 손실").
   - 손실이 결과 글자의 절반을 넘으면 "복원 불가에 가까움" 라벨.
7. **결과 화면**
   - 상위 후보 최대 5개를 목록으로 표시. 한 항목: 복원 결과(긴 경우 말줄임) / 복원 경로 / 라벨(일부 손실 등) / 원인 힌트 1줄.
   - 선택 항목의 전체 결과와 상세 경로는 아래 상세 영역에 표시.
   - ↑/↓ 이동, Enter 선택 시 결과를 클립보드에 복사하고 창 닫기, Esc 닫기, 포커스 잃으면 닫기.
   - 경로 표기 예: `URL 디코딩 → UTF-8 바이트를 CP949로 읽음 (되돌림)`
8. **원인 힌트**
   - `hints.json`에서 경로 패턴별 힌트 문구를 읽어 표시한다. 기본 동봉 예:
     - UTF-8을 CP949로 읽음: "UTF-8 데이터를 MS949/EUC-KR로 읽음. JSP pageEncoding, 응답 Content-Type charset, JVM file.encoding, 터미널/로그 뷰어 인코딩 확인"
     - CP949를 Latin-1로 읽음: "EUC-KR/MS949 데이터를 ISO-8859-1로 읽음. 요청 파라미터 인코딩(request.setCharacterEncoding, Tomcat URIEncoding), 서블릿 필터 확인"
     - CP949를 UTF-8로 읽음: "MS949 데이터를 UTF-8로 읽음. 원본이 손실되었을 가능성 높음. 파일 저장 인코딩, DB NLS_CHARACTERSET 확인"
     - `\u` 이스케이프: "properties 파일 native2ascii 결과이거나 JSON 직렬화 이스케이프"
     - URL 인코딩: "URL/폼 파라미터 인코딩. 이중 인코딩이면 인코딩 필터가 두 번 적용됐는지 확인"
   - 맞는 힌트가 없으면 힌트 줄을 생략한다.

## 4. 입력과 데이터
- 입력: 클립보드 텍스트(CF_UNICODETEXT). 줄바꿈 보존.
- 동봉 데이터:
  - `data/syllable_freq.json`: 한글 음절 빈도 등급표 (KS X 1001 완성형 2,350자 기준 등급 + 그 외)
  - `defaults/hints.json`: 원인 힌트 규칙
  - `defaults/config.json`:
    ```json
    {
      "hotkey": "win+shift+k",
      "fallback_hotkey": "ctrl+alt+k",
      "max_depth": 3,
      "max_candidates": 5,
      "max_input_chars": 20000
    }
    ```
- 사용자 데이터: `%APPDATA%\hangul-restore\` 에 `config.json`, `hints.json` (없으면 기본값 복사). 저장하는 사용 기록 없음.

## 5. 엣지 케이스와 처리 규칙
| 상황 | 처리 |
|---|---|
| 클립보드가 비었거나 이미지 등 비텍스트 | 빈 입력란 + "클립보드에 텍스트가 없습니다" |
| 입력이 이미 정상 한글/영문 | "깨진 부분을 찾지 못했습니다", 원문 1위 |
| 짧은 영단어가 Base64 형식에 맞음 (`test`, `admin`) | 디코딩 결과가 유효한 한글이 아니면 후보 제외 |
| 결과가 한자/가나로 그럴듯하게 나옴 | 정답으로 보지 않고 감산 (한국어 전용) |
| `%`가 들어 있지만 URL이 아님 (`50%`) | 유효한 `%XX` 연속이 아니면 URL 연산 적용 안 함 |
| `\u` 뒤 16진수 부족, 홀로 남은 서로게이트 | 해당 부분은 원문 유지 |
| `?`나 `�`로 이미 대체된 바이트 | 부분 복원 + `□` + "일부 손실" 라벨 |
| 손실이 결과의 절반 초과 | "복원 불가에 가까움" 라벨 |
| 탐색 결과 후보 0개 | "복원 후보를 찾지 못했습니다" + 원문 표시 |
| 이중/삼중 인코딩 | 3단계 이내면 복원, 넘으면 중간 결과를 후보로 표시 |
| 매우 긴 입력 | `max_input_chars`까지만 처리하고 안내 |
| 의심 구간 분할 실패 | 전체를 한 덩어리로 본 후보와 경쟁해 점수 높은 쪽 |
| 클립보드 쓰기 실패 (다른 앱이 잠금) | 짧게 재시도 후 트레이 알림 |
| 단축키 등록 실패 | 보조 키 등록 + 알림 |
| `hints.json`, `config.json` 깨짐 | 기본값으로 동작, 트레이 경고, 파일 덮어쓰지 않음 |
| 중복 실행 | 이름 있는 뮤텍스로 두 번째 실행 즉시 종료 |

## 6. 제약
- 실행 환경: Windows 10/11 (회사 PC DLP 환경 포함). pip 사용 가능.
- 기술 스택: Python 3.10 이상. 코어는 **표준 라이브러리만** (`codecs`, `urllib.parse`, `html`, `base64`, `unicodedata`). UI/트레이는 PySide6 (emoji-searcher와 동일), 전역 단축키는 `ctypes` `RegisterHotKey`.
- 입력 훅, 선택 영역 자동 복사(SendInput Ctrl+C) 사용 안 함.
- 네트워크 사용 없음.
- 공개 레포이므로 테스트 데이터에 실제 고객사명, 개인정보를 넣지 않는다.

## 7. 관련 파일과 인터페이스
```
small-win-tools/
├─ README.md                    ← 도구 목록에 hangul-restore 한 줄 추가
└─ hangul-restore/
   ├─ SPEC.md
   ├─ README.md                 ← 사용법, 지원 깨짐 유형 예시, 힌트 추가 방법
   ├─ requirements.txt          ← PySide6, pytest
   ├─ hangul_restore.pyw        ← 진입점

   │  ├─ decoders.py            ← 복원 연산
   │  ├─ search.py              ← 3단계 탐색, 가지치기
   │  ├─ segment.py             ← 정상/의심 구간 분할, 부분 복원 조합
   │  ├─ score.py               ← 한글다움 점수, 손실 판정
   │  └─ hints.py               ← 경로 → 힌트
   ├─ app/
   │  ├─ main.py                ← 트레이, 뮤텍스, 단축키
   │  └─ window.py              ← 팝업 UI
   ├─ data/
   │  └─ syllable_freq.json
   ├─ defaults/
   │  ├─ config.json
   │  └─ hints.json
   └─ tests/
      ├─ test_decoders.py
      ├─ test_search.py
      ├─ test_segment.py
      ├─ test_score.py
      ├─ gen_corruptions.py     ← 정상 문장을 일부러 깨뜨려 테스트 케이스 생성
      ├─ corpus.txt             ← 정상 한글 문장 (그룹웨어/개발 용어, 직접 작성한 예문)
      └─ real_cases.json        ← 실제로 만난 깨진 문자열 (CG가 추가, 처음엔 아래 예시만)
```
- 코어 공개 함수:
  ```python
  restore(text: str, config) -> list[Candidate]
  # Candidate: result, score, path(list[str]), lost_chars(int), labels(list[str]), hint(str|None)
  ```
- 코어는 UI 없이 `python -m restore "寃곗옱"` 같은 방식으로도 확인할 수 있게 `__main__`을 둔다 (디버그용, README에는 부가 기능으로만 언급).

## 8. 결정 사항과 근거
| 결정 | 이유 | 버린 대안 |
|---|---|---|
| 트레이 + 단축키 팝업 | 깨진 문자열을 본 즉시 해독 | 필요할 때 실행하는 창 |
| 클립보드 입력 | 모든 앱에서 동일, 터미널 Ctrl+C 위험 회피 | 선택 영역 자동 복사 |
| 문자열만 | 범위 최소화 | 파일 인코딩 판별 |
| 깨진 구간만 부분 복원 | 로그 한 줄에 영문과 섞인 경우가 대부분 | 전체 한 덩어리 |
| 최대 3단계 | 이중 인코딩까지 잡고 엉뚱한 후보 억제 | 2단계, 4단계 이상 |
| Base64는 한글 결과만 | 짧은 영단어 오탐 방지 | 형식만 맞으면 해독 |
| 부분 복원 + □ 표시 | 남은 정보라도 살려서 원인 파악 | 복원 불가 판정만 |
| 후보 목록 + Enter 복사 | 1위가 틀릴 때 대안 확인 | 1위만 표시 |
| 경로 + 원인 힌트(규칙 파일) | 고치는 데서 끝나지 않고 원인 추적 | 경로만 |
| 코어 표준 라이브러리만 | 회사 PC 설치 부담 최소, 테스트 용이 | 외부 인코딩 감지 라이브러리 |
| 한국어 전용 판정 | 목적이 한글 복원, 오탐 감소 | 다국어 |
| Win+Shift+K | 사용자 지정 | Ctrl+Alt+K (보조 키로 유지) |

## 9. 가정 (사용자가 위임한 판단)
- 오독 인코딩 후보는 cp949, euc-kr, latin-1, cp1252 / 원래 인코딩은 utf-8, cp949로 한정한다. (EUC-KR은 CP949의 부분집합이라 원래 인코딩 쪽에서는 CP949로 통합)
- 점수 기준과 가중치는 구현자가 정하되, 11번 테스트 통과율로 조정한다.
- 음절 빈도표는 KS X 1001 완성형 2,350자를 "일반 음절"로 보는 단순 기준으로 시작한다.
- UI 형태(창 크기, 글꼴)는 emoji-searcher와 비슷하게 맞춘다.

## 10. 미결 사항

## 11. 검증 계획
- **정답 샘플**
  - 자동 생성: `gen_corruptions.py`가 `corpus.txt`의 정상 문장 각각에 대해 아래 깨짐을 1~3단계로 적용한 케이스를 만든다. 정답은 원문이므로 확실하다.
    - 오독: utf-8→cp949, cp949→latin-1, cp949→cp1252, utf-8→latin-1
    - URL(UTF-8, CP949), `\u` 이스케이프, HTML 엔티티(10진, 16진), Base64
    - 2단계 조합: URL(오독 결과), 이스케이프(오독 결과), Base64(URL) 등
    - 섞인 입력: 영문 로그 접두/접미 + 깨진 한글
    - 손실 케이스: 오독 시 `errors="replace"`로 바이트를 잃게 만든 것 (정답 대신 "일부 손실" 라벨과 손실 수 범위로 판정)
  - 고정 예시 (`real_cases.json` 초기값):

    | 입력 | 기대 |
    |---|---|
    | `寃곗옱` | `결재` (UTF-8을 CP949로 읽음) |
    | `°áÀç` | `결재` (CP949를 Latin-1로 읽음) |
    | `%EA%B2%B0%EC%9E%AC` | `결재` |
    | `결재` | `결재` |
    | `&#44208;&#51116;` | `결재` |
    | `6rKw7J6sIOyalOyyrSDsmYTro4w=` | `결재 요청 완료` |
    | `%E5%AF%83%EA%B3%97%EC%98%B1` | `결재` (URL → UTF-8을 CP949로 읽음, 2단계) |
    | `test`, `admin` | 후보 없음 (정상 입력) |
    | `50% 완료` | 원문 유지 |

- **자동 테스트 (pytest)**
  - 기준: 손실 없는 자동 생성 케이스에서 **정답이 1위 95% 이상, 상위 3위 안 99% 이상**. 고정 예시는 100% 1위.
  - 손실 케이스: "일부 손실" 라벨이 붙고 손실 글자 수가 실제와 ±1 이내.
  - 정상 입력(오탐 방지): 정상 한글/영문 문장 100개에서 원문이 1위, 그 외 후보 점수가 원문보다 낮을 것.
  - 섞인 입력: 정상 구간이 바뀌지 않을 것.
  - 성능: 2KB 입력 1회 처리 200ms 이내 (CI가 없으므로 로컬 측정).
  - 코어 모듈에 PySide6 등 외부 import가 없을 것.
- **End-to-end 검증 (마지막에 실행해 통과해야 완료)**
  1. `pip install -r requirements.txt` 후 `pytest` 전체 통과
  2. `hangul_restore.pyw` 실행 → 트레이 아이콘
  3. 메모장에서 `寃곗옱` 복사 → Win+Shift+K → 1위 `결재`, 경로와 힌트 표시 → Enter → 메모장에 붙여 `결재` 확인
  4. 로그 한 줄(`ERROR userNm=` + 깨진 이름 + ` id=1004`) 복사 → 앞뒤 영문 유지, 가운데만 복원
  5. 손실 케이스 복사 → □ 표시와 "일부 손실" 라벨
  6. `test` 복사 → "깨진 부분을 찾지 못했습니다"
  7. 이미지가 클립보드에 있을 때 → 안내 문구, 오류 없음
  8. 회사 PC에서 1~7 반복
