# hangul-restore 🔤

깨진 한글을 클립보드에 복사하고 **Win+Shift+K** 한 번 누르면 원래 글자로 되돌려 주는 작은 도구예요.
되돌린 결과와 함께 **어디서 어떻게 깨졌는지**(복원 경로와 의심 지점)도 알려 줘요.

레거시 Java/Tomcat/Oracle 환경에서 자주 보는 이런 것들을 풀어요.

| 이렇게 보이면 | 이렇게 돌려줘요 | 무슨 일이 있었나 |
|---|---|---|
| `寃곗옱` | `결재` | UTF-8 바이트를 CP949(MS949)로 읽음 |
| `°áÀç` | `결재` | CP949 바이트를 Latin-1(ISO-8859-1)로 읽음 |
| `ê²°ìž¬` | `결재` | UTF-8 바이트를 CP1252(Latin-1)로 읽음 |
| `%EA%B2%B0%EC%9E%AC` | `결재` | URL 인코딩 (UTF-8, CP949 둘 다) |
| `%E5%AF%83%EA%B3%97%EC%98%B1` | `결재` | URL 디코딩 → UTF-8을 CP949로 읽음 (2단계) |
| `\uacb0\uc7ac` | `결재` | 유니코드 이스케이프 (properties, JSON) |
| `&#44208;&#51116;` | `결재` | HTML 엔티티 |
| `6rKw7J6sIOyalOyyrSDsmYTro4w=` | `결재 요청 완료` | Base64 (결과가 한글일 때만) |
| `ERROR userNm=�솉湲몃룞 id=1004` | `ERROR userNm=□길동 id=1004` | 깨진 구간만 복원, 잃은 글자는 □ |
| `'��뿩��'` | `'□□여□'` | CP949를 UTF-8로 읽어 바이트가 �로 바뀜 (대부분 손실) |

- 로그 한 줄처럼 영문과 섞여 있으면 **깨진 구간만** 고치고 나머지는 그대로 둬요.
- 연산을 최대 3단계까지 조합해서 찾아요 (이중 URL 인코딩 같은 것).
- 후보를 최대 5개 보여 주고, 1위가 틀렸으면 ↑↓로 골라 Enter.
- 실행 중에는 인터넷을 전혀 안 써요. 사용 기록도 저장하지 않아요.

## 설치

Python 3.10 이상이 필요해요.

```bash
cd small-win-tools/hangul-restore
```

```bash
pip install -r requirements.txt
```

> 깜빡하고 바로 실행해도 괜찮아요. PySide6가 없으면 처음 실행할 때 설치할지 물어봐요.
> 인터넷이 막힌 PC라면 [emoji-searcher의 오프라인 설치](../emoji-searcher/README.md#오프라인-설치-인터넷이-막힌-pc) 방법과 같아요.

## 실행

```bash
pythonw hangul_restore.pyw
```

창은 안 뜨고 트레이에 파란 **한** 아이콘이 생겨요.

1. 깨진 문자열을 아무 데서나 복사 (Ctrl+C)
2. **Win+Shift+K**
3. 1위 후보 확인 → **Enter**를 누르면 결과가 클립보드에 들어가고 창이 닫혀요
4. 원래 자리에 Ctrl+V

> Win+Shift+K 등록에 실패하면(다른 프로그램이 쓰는 중) **Ctrl+Alt+K** 로 대신 등록하고 트레이 알림으로 알려 드려요.
> 둘 다 안 되면 트레이 아이콘을 클릭하거나 메뉴의 **열기**로 쓰면 돼요.

### 팝업 화면

| 키 | 동작 |
|---|---|
| ↑ / ↓ | 후보 이동 |
| Enter, 더블클릭 | 선택한 결과를 클립보드에 복사하고 닫기 |
| Esc, 창 밖을 마우스로 클릭 | 닫기 (키보드를 치거나 한/영을 바꿔도 창은 안 닫혀요) |
| Ctrl+V, Win+V로 고르기 | 그 내용으로 입력을 바꿔 다시 해독 (Win+V 창·시작 메뉴를 눌러도 팝업은 안 닫혀요) |
| 글자 입력 | 입력란 끝에 들어가고 바로 다시 해독 |
| 입력란 클릭 후 수정 | 바로 다시 해독 |
| (입력란에서) Ctrl+Enter, Ctrl+↑↓ | 선택, 후보 이동 |

후보마다 이런 걸 보여 줘요.

- **결과**: 잃은 글자는 `□`
- **경로**: 예) `URL 디코딩 (UTF-8) → UTF-8 바이트를 CP949로 읽음 (되돌림)`
- **라벨**: `일부 손실`, `3글자 손실`, `복원 불가에 가까움`(잃은 글자가 절반 넘음), `원문`
- **💡 원인 힌트**: 어디를 확인하면 되는지 한 줄

아래 상세 영역에는 전체 결과, 구간별 복원 내역, 점수가 나와요.
입력이 이미 멀쩡하면 "깨진 부분을 찾지 못했습니다"라고 하고 원문을 1위에 둬요.

### 이미 잃은 글자 (`�`, `?`)에 대해

`�`나 `?`로 이미 바뀐 바이트는 어디에도 남아 있지 않아서 **되살릴 수 없어요.**
이 도구는 남은 바이트로 맞출 수 있는 글자만 살리고 나머지 자리를 `□`로 표시해요.

특히 **CP949(MS949)로 저장된 한글을 UTF-8로 읽은 경우**(예: `'��뿩��'`)는 한 글자 2바이트 중
대부분이 `�`로 바뀌어 거의 다 사라져요. 이때 이 도구가 해 줄 수 있는 건 **"CP949 데이터를 UTF-8로 읽었다"는 진단**과
살아남은 몇 글자예요. 원본 파일이나 DB 값을 다시 받아야 해요.

## 트레이 메뉴

- **열기**: 클립보드 내용으로 팝업 열기
- **데이터 폴더 열기**: `%APPDATA%\hangul-restore\`
- **설정·힌트 다시 읽기**: `config.json`, `hints.json` 고친 걸 바로 반영
- **종료**

## 설정 (`%APPDATA%\hangul-restore\config.json`)

```json
{
  "hotkey": "win+shift+k",
  "fallback_hotkey": "ctrl+alt+k",
  "max_depth": 3,
  "max_candidates": 5,
  "max_input_chars": 20000
}
```

- `max_depth`: 연산을 몇 단계까지 조합할지
- `max_input_chars`: 이보다 길면 앞부분만 처리하고 알려 줘요
- 파일이 깨져 있으면 기본값으로 동작하고 트레이로 알려 줘요 (파일은 건드리지 않아요)

## 원인 힌트 추가하기 (`%APPDATA%\hangul-restore\hints.json`)

복원 경로에 `steps` 중 하나라도 들어 있으면 `hint`를 보여 줘요. 위에서부터 **처음 맞는 규칙 하나**만 써요.
`min_count`를 주면 그 횟수 이상 들어 있을 때만 맞아요 (예: URL 디코딩 2번 = 이중 인코딩).

```json
{
  "rules": [
    {"steps": ["url_utf8", "url_cp949"], "min_count": 2, "hint": "URL 인코딩이 두 번 적용됨 ..."},
    {"steps": ["utf8_as_cp949"], "hint": "우리 팀 로그 뷰어 인코딩을 UTF-8로 바꾸세요"}
  ]
}
```

연산 id 목록:

| id | 뜻 |
|---|---|
| `utf8_as_cp949` | UTF-8 바이트를 CP949로 읽음 → 되돌림 |
| `utf8_as_euckr` | UTF-8 바이트를 EUC-KR로 읽음 → 되돌림 |
| `cp949_as_latin1` | CP949 바이트를 Latin-1로 읽음 → 되돌림 |
| `cp949_as_cp1252` | CP949 바이트를 CP1252로 읽음 → 되돌림 |
| `cp949_as_utf8` | CP949 바이트를 UTF-8로 읽음 → 되돌림 (대개 손실) |
| `utf8_as_latin1` | UTF-8 바이트를 Latin-1로 읽음 → 되돌림 |
| `utf8_as_cp1252` | UTF-8 바이트를 CP1252로 읽음 → 되돌림 |
| `url_utf8`, `url_cp949` | URL 디코딩 |
| `unicode_escape` | `\uXXXX` 이스케이프 해제 |
| `html_entity` | HTML 엔티티 해제 |
| `base64_utf8`, `base64_cp949` | Base64 디코딩 |

## 덤: 명령줄로 확인하기 (디버그용)

```bash
python -m restore "寃곗옱"
```

후보, 경로, 점수, 힌트를 그대로 찍어 줘요. 인자 없이 실행하면 표준 입력을 읽어요.

## 테스트

```bash
python -m pytest -q
```

`tests/gen_corruptions.py`가 `tests/corpus.txt`의 정상 문장을 일부러 깨뜨려(오독, URL, 이스케이프, 엔티티, Base64, 2~3단계 조합, 로그 섞기, 바이트 손실) 정답을 아는 케이스를 만들어요.
실제로 만난 깨진 문자열은 `tests/real_cases.json`에 추가하면 돼요 (공개 저장소라 고객사명·개인정보는 빼고).

## 동작 방식 (짧게)

1. 입력을 정상 구간과 의심 구간(깨진 글자 묶음, `%XX` 토큰, `\u` 연속, `&#..;` 연속, Base64 토큰)으로 나눠요.
2. 의심 구간마다 복원 연산을 최대 3단계까지 조합해 봐요 (BFS). 같은 결과는 짧은 경로만 남겨요.
3. 결과마다 "한글다움" 점수를 매겨요. 자주 쓰는 음절은 가산, `�`·제어 문자·희귀 음절·새로 생긴 한자/가나는 감산.
4. 구간별 최선 결과를 이어 붙인 후보와 전체를 한 덩어리로 푼 후보를 함께 경쟁시켜요.
5. `�`·`?`로 잃은 바이트는 "모르는 바이트"로 두고, 남은 바이트로 글자 경계를 맞춰(동적 계획법) 맞출 수 있는 글자만 살려요.

음절 빈도표(`data/syllable_freq.json`)는 `tools/build_syllable_freq.py`로 만들어요.
